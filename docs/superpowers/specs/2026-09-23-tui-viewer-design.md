# TUI 观看器设计文档

## 概述

为 whoisspy 后端添加终端 TUI 观看器，通过 `python -m app.main --tui` 启动，实时显示对局对话流，支持调试和流程查看。不依赖前端 web 界面。

**目标用户：** 开发者、调试人员、终端爱好者

**使用场景：** 实时追更对局流程，查看对话、夜晚操作、投票结果，方便调试

---

## 架构

### 模块结构

```
backend/app/tui/
├── __init__.py
├── main.py          # TUI 入口，事件循环，键盘交互
├── display.py       # 终端渲染（座次表、阶段指示、对话流）
└── sse_client.py    # 连接后端 SSE 流，去重、重连
```

### 启动流程

1. `python -m app.main --tui` → 启动 web 服务（后台）+ 打开 TUI 终端
2. TUI 通过 SSE 连接到 `localhost:8000/api/matches/{id}/stream?view=god`
3. 接收事件 → 投影到 ViewModel → 渲染到终端

### 依赖

- `rich` 或 `textual`（终端 UI 库）
- 复用现有的事件投影逻辑（与前端共享）

## 终端布局

### 屏幕分区（上/下结构）

```
┌─────────────────────────────────────────┐
│ 座次表：1✓ 2✗ 3✓ 4✓ 5✓ 6✓            │  ← 座位状态（存活/死亡/身份）
│ 当前：第2天 · 白天发言                  │  ← 阶段指示
├─────────────────────────────────────────┤
│ [第一夜]                                │
│   3号: 我查验了2号，是狼人              │  ← 对话流
│   狼队选择击杀 5号                      │
│   昨夜死亡：5号                        │
│ [第一天]                                │
│   1号: 我认为3号可疑...                │
│   2号 投票给 3号                       │
│ ...                                     │
└─────────────────────────────────────────┘
```

### 功能

- **座次表：** 显示座位号 + 存活状态（✓/✗）+ 角色（god 视角）
- **阶段指示：** 当前第几天/什么阶段
- **对话流：** 按天/夜分段，自动滚动

---

## 事件流与交互

### 数据流

1. TUI 启动 → 连接 SSE (`view=god`，获取完整视角)
2. 接收事件 → 去重（按 seq）→ 投影到 ViewModel
3. 触发终端重绘（防抖：100ms 内多个事件合并为一次重绘）

### 键盘交互

- `q` / `Ctrl+C`：退出 TUI
- `g`：切换视角（god ↔ immersive）
- `↑/↓` 或 `PageUp/Down`：滚动对话历史

### 错误处理

- **SSE 断线：** 显示"连接断开，重连中..." → 自动重试（带 `Last-Event-ID`）
- **后端未启动：** 显示错误信息并退出

## 测试策略

### 单元测试（TDD）

- `test_display.py`：验证终端渲染逻辑（输入事件 → 输出字符串）
- `test_sse_client.py`：验证 SSE 消费、去重、重连逻辑
- `test_viewmodel.py`：验证事件 → ViewModel 投影（与前端共享）

### 集成测试

- 启动后端 + TUI，模拟 SSE 流，验证终端输出包含预期对话

### 测试覆盖目标

- 渲染逻辑：100%（纯函数，易测）
- SSE 客户端：80%（错误路径：断线、重连）
- 键盘交互：50%（手动验证即可）

### 依赖

- `pytest` + `pytest-asyncio`（已有）
- `textual[dev]` 或 `rich`（新增）

## 实现范围

### Phase 1：核心功能

1. SSE 客户端（连接、去重、重连）
2. 终端渲染（座次表、阶段指示、对话流）
3. 键盘交互（退出、视角切换、滚动）
4. 启动参数集成（`--tui`）

### Phase 2：优化

1. 事件防抖（合并高频事件）
2. 错误恢复（断线重连）
3. 配置选项（端口、match_id、视角默认值）

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| `textual` 依赖较大 | 增加安装时间 | 可选依赖，`pip install whoisspy[tui]` |
| SSE 高频事件导致闪烁 | 用户体验差 | 防抖机制（100ms 合并） |
| 跨平台兼容性 | Windows/macOS/Linux 差异 | 用 `rich` 或 `textual` 抽象层 |
| 端口冲突 | 后端已在运行 | 检测并复用现有后端 |
